# Assignment 3: Responsive Product Detail Page

## "Hello, World"

"Hello, World" is the traditional first program every coder writes — a simple message that confirms everything is connected and working. In web design, your first responsive page serves the same purpose: proof that you understand how content adapts across devices.

## The Assignment

Design a responsive Product Detail Page (PDP) for both mobile and desktop, tailored to a specific persona's needs and values. You'll research a fictional character, then make design decisions based on what *they* would prioritize when shopping for a product.

### Product Detail Page

💚 Design for both mobile AND desktop viewports (same product, responsive layout)
💚 Include all required content elements (see C1 requirements below)
💚 Build on a consistent grid system with clear alignment
💚 Typography hierarchy should guide the user through the page
💚 Design decisions should reflect your persona's priorities and job-to-be-done
❌ You do NOT need to create a page footer or navigation bar
❌ Do not just copy an existing PDP — make intentional choices for your persona

### Persona

💚 Choose a character from the provided list OR create your own research persona
💚 Include: background information (demographics, interests, family life), core values, and job-to-be-done
💚 Your design choices should clearly connect to your persona's needs
❌ The visual design doesn't need to "look like" the character (no cartoon styling for a cartoon character)

### Rubric

| Criterion | Beginning (1) | Developing (2) | Proficient (3) | Exemplary (4) |
|-----------|---------------|----------------|----------------|---------------|
| **Conceptual Depth & Novelty** | Persona is vague or design shows no connection to user needs; hierarchy appears random | Persona is defined but design choices don't clearly reflect their priorities; some hierarchy present | Clear persona with documented values; design decisions explicitly tied to user needs; logical hierarchy | Deep persona research with nuanced understanding; every design choice justified by user context; hierarchy creates a compelling narrative |
| **Testing & Iteration** | No evidence of user testing or iteration | Some testing conducted but changes aren't documented or are superficial | Clear testing with 2+ users; documented findings; specific changes made in response | Rigorous testing with clear methodology; insightful analysis of findings; significant improvements visible between versions |
| **Responsive Design & Grid** | Layout breaks or becomes unusable at different sizes; no visible grid structure | Basic responsiveness but inconsistent; grid present but elements misaligned | Solid responsive behavior; consistent grid; content reflows logically between breakpoints | Masterful responsive design; grid is invisible but impeccable; mobile and desktop feel intentionally crafted (not just scaled) |
| **Typography & Visual Hierarchy** | Type choices unclear or inconsistent; no discernible hierarchy; hard to scan | Basic type system but hierarchy is weak; some inconsistency in application | Clear type scale with defined styles; hierarchy guides the eye; consistent application throughout | Exceptional type system that enhances meaning; hierarchy creates effortless reading flow; type choices reinforce brand and persona |
| **Process Documentation** | Incomplete documentation; missing key stages; no connection between persona and design | Documentation shows stages but gaps exist; persona-to-design connection is unclear | Complete documentation showing progression; clear thread from persona research through final design | Comprehensive documentation that tells the project's story; persona insights visibly drive each design decision |

## Process

### C1: Persona Sheet + Product Details
**Due: Feb 11 @ 5:15pm**

Submit a PDF slide deck with:

**Persona Sheet:**
- Background information (demographics, interests, family life)
- Core values (what matters to them?)
- Job-to-be-done (what are they trying to accomplish?)

**Product Details:**
Choose a product that suits your persona and gather:
- Product name
- At least 3 quality product images
- Price
- How to use / product directions
- Set contents (if applicable)
- Shipping information
- Reviews
- Similar or related products
- Exchanges and returns policy
- Product dimensions

**Optional content to consider:**
- Announcement bar
- Subscribe option
- Price differences for sets
- Gifting information
- Company replies to reviews
- Out-of-stock messaging
- Gift wrapping options

---

### C2: Type Hierarchy
**Due: Feb 17 @ 5:15pm**

Create a type stylesheet in Figma defining:
- H1, H2, H3, Paragraph (and any additional styles needed)
- Colors
- Logo for your product/brand

Export as PDF. These styles will evolve as you design, but you need a starting point that reflects hierarchy standards.

---

### C3: Mobile + Desktop Wireframes
**Due: Feb 18 @ 11:59pm**

Create simple wireframes for both mobile and desktop PDPs showing:
- Product title + details placement
- Image placements
- Button placements
- Overall page layout and grid structure

These are structural — focus on layout, not visual polish.

---

### C4: High Fidelity V1 + Testing
**Due: Feb 23 @ 11:59pm**

1. Transform wireframes into high-fidelity designs for both desktop and mobile
2. Conduct user testing with at least 2 people using your own test script
3. Submit PDF with:
   - High-fidelity designs (both viewports)
   - Summary of testing results
   - What you plan to change based on feedback

---

## C5: Final High Fidelity Designs
**Due: Feb 25 @ 5:15pm**

Submit a single PDF containing:

**Final Designs:**
- Desktop PDP (full page length, no cropping)
- Mobile PDP (full page length, no cropping)

**Process Documentation:**
- Persona sheet + job-to-be-done
- Typography stylesheet
- Wireframes
- Any saved iterations showing your progression

### Specifications

- **Mobile:** Choose a frame size matching your target phone width; extend height as needed
- **Desktop:** Standard desktop width; extend height as needed
- **Format:** Single PDF with all pages
- Export full page lengths — don't crop

## How to Know You Did It Right

1. Did you include all required content on your page?
2. Is your page clear and easy to navigate?
3. Is your page built on a strong grid system with aligned elements?
4. Does your layout reflect your persona's needs and job-to-be-done?
5. Does your type hierarchy guide users through the content?
6. Does your design work on both mobile and desktop?
