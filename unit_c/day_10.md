# Day 10 — Wednesday, Feb 11
## Unit C: Hierarchy & Responsive Web

**Focus:** Typography is structure — hierarchy, readability, and personality all flow from type choices.

**Targeted Learning Outcomes:**
- Better Interactions & Experiences
- Critical Analysis of Form and Format
- Design Strategy

---

### Desired Results

**Essential Questions:**
- EQ1: Why does typography matter more than any other visual element in interface design?
- EQ2: How do style sheets create consistency and speed up design decisions?
- EQ3: What's the relationship between content structure and visual hierarchy?

**Understandings:**
- U1: Typography creates hierarchy — it tells users what to read first, second, and third
- U2: Figma text styles enforce consistency and save time
- U3: Content structure should drive visual hierarchy decisions

**Students Will Know:**
- K1: How type scales work (ratios, sizes, hierarchy)
- K2: The difference between system typography and brand typography
- K3: How to set up reusable text styles in Figma

**Students Will Be Able To:**
- S1: Create a type stylesheet in Figma with defined hierarchy
- S2: Apply type hierarchy to guide users through a page

### Activities

1. **Warm-Up: Type Hierarchy Scavenger Hunt** (10 min) `[EQ1, U1, K2]`
   - Prompt: "Find a product page (any brand). Screenshot it. Circle and label: H1, H2, H3, body text, caption."
   - Students identify hierarchy levels on a real PDP
   - Quick share: 2-3 students show their examples on screen
   - Sets up the question: how do we *create* hierarchy, not just identify it?

2. **Today's Learning Goals** (5 min) `[EQ1, EQ2, EQ3, U1, U2, U3]`
   - Today's focus: typography as the foundation of interface design
   - Connection to forming/rendering: type choices *render* your intent about what matters most
   - We'll learn: how type scales work, how style sheets enforce consistency, and how HTML structures content
   - By end of class: you'll have a working type stylesheet for your PDP

3. **Direct Instruction: Typography Systems & Style Sheets** (25 min) `[K1, K2, K3, U1, U2, S1]`
   - **I do:** Explain type scales and hierarchy
     - What is a type scale? (ratios: 1.25, 1.333, 1.5, etc.)
     - Demo: typescale.com — show how scales create natural hierarchy
     - The minimum viable type system: H1, H2, H3, Body, Caption
     - Weight, size, and spacing all contribute to hierarchy
   - **I do:** Demo creating Figma text styles
     - Define styles: name, size, weight, line-height
     - Show how styles update globally
     - Best practice: name styles semantically (H1, Body) not visually (Big Bold, Small)
   - **We do:** Apply type thinking to PDP content
     - What's the H1? (product name)
     - What are H2s? (section headers: reviews, shipping, etc.)
     - What's body text vs. caption?
   - **You do:** Students identify the hierarchy structure of their own PDP content (5 min)

4. **Introduce C2: Type Hierarchy** (10 min) `[S1, K2, K3]`
   - **Due: Feb 17 @ 5:15pm** (but start now)
   - Requirements:
     - Define H1, H2, H3, Paragraph (+ any additional styles needed)
     - Choose colors for your product/brand
     - Include a logo (can be simple/placeholder)
   - Export as PDF
   - Note: These styles will evolve — this is a starting point, not final
   - Show 1-2 examples of type stylesheets (good and bad)

5. **Work Session: C1 Finalization + C2 Type Stylesheet** (130 min) `[S1, S2]`
   - **First priority:** Finish C1 if not complete (due 5:15pm today)
   - **Second priority:** Begin C2 type stylesheet
     - Choose typefaces (Google Fonts, Adobe Fonts, or system fonts)
     - Set up type scale using typescale.com as reference
     - Create Figma text styles
   - Instructor circulates for 1:1 feedback:
     - Is the type scale creating clear hierarchy?
     - Do the type choices fit the persona/brand?
     - Is the stylesheet set up for reuse (named styles, not one-off formatting)?

**Total: 180 min**
