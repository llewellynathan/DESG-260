# Day 5 — Monday, Jan 26
## Unit B: Make It Better App

**Focus:** Understanding why something was designed a certain way is the first step to improving it.

**Targeted Learning Outcomes:** Problem Discovery & Research, Familiarity and Distinctiveness

---

### Desired Results

**Essential Questions:**
- EQ1: How do we identify what's broken in an existing product—and how do we know our fix is actually better?
- EQ2: What makes a design "good" for users? How do we move beyond personal preference to make design decisions grounded in user needs?

**Understandings:**
- U1: Improving an existing product requires both forming better intent (discovering what's actually broken and for whom) and rendering that intent (executing improvements with appropriate craft).
- U2: Improving an existing product requires understanding why it was designed that way in the first place.
- U3: Good design is often invisible. Users notice friction, confusion, and frustration—not seamless experiences.

**Students Will Know:**
- K1: The vocabulary and concepts of user experience design (affordances, signifiers, feedback, mental models)
- K2: Nielsen's 10 Usability Heuristics as a framework for evaluating interfaces
- K3: Methods for conducting competitive analysis
- K4: How to document an existing user flow with screenshots and annotations

**Students Will Be Able To:**
- S1: Analyze existing products to identify strengths, weaknesses, and opportunities
- S2: Conduct user research using interviews, observation, and competitive analysis

### Activities

1. **Warm-Up: Process Book Review** (10 min) `[U1]`
   - Display 2-3 exemplary process books from previous semesters (projected or printed)
   - Students independently study how documentation tells the story of design decisions
   - Write: What makes this documentation effective? What would you steal for your own work?

2. **Today's Learning Goals** (5 min) `[EQ1, EQ2, U1, U2, U3, K1, K2, K3, S1, S2]`
   - Today we shift from high level experience mapping (Unit A) to improving existing experience
   - Key insight: Before you can fix something, you must understand *why* it was designed that way
   - Preview: We'll learn UX vocabulary, heuristic analysis, mapping an existing user flow, and competitive analysis—then you'll start analyzing your chosen app

3. **Direct Instruction: UX Vocabulary, Heuristics & User Flow Mapping** (25 min) `[EQ1, EQ2, U2, U3, K1, K2, K4]`

   **Part A: UX Vocabulary** (10 min)
   - **I do:** Define core UX concepts from Norman Ch. 1:
     - **Affordances** — what actions are possible (a button affords pressing)
     - **Signifiers** — what indicates where action should take place (the button's visual appearance)
     - **Feedback** — what communicates the result of an action (button depresses, screen changes)
     - **Mental models** — how users think the system works vs. how it actually works
   - These are what you analyze *at each step* of an experience

   **Part B: Heuristic Analysis** (10 min)
   - **I do:** Introduce Nielsen's 10 Usability Heuristics as a framework for evaluating interfaces:
     1. Visibility of system status
     2. Match between system and real world
     3. User control and freedom
     4. Consistency and standards
     5. Error prevention
     6. Recognition rather than recall
     7. Flexibility and efficiency of use
     8. Aesthetic and minimalist design
     9. Help users recognize, diagnose, and recover from errors
     10. Help and documentation
   - Heuristics give you language to describe *why* something feels broken
   - Connect to Day 5 focus: Understanding why something was designed helps you improve it
   - **We do:** Quick heuristic evaluation—pick a familiar app's friction point and identify which heuristics it violates

   **Part C: Mapping an Existing User Flow** (5 min)
   - **I do:** Demonstrate the 3-step method for documenting an app's current state:
     1. **Screenshot:** Dissect the app's flow into a series of screenshots
     2. **Annotate:** Add arrows or circles indicating flow between screens
     3. **Describe:** Write out the user's actions underneath each screen
   - This is exactly what you'll create for B1 today
   - Show example of a completed user flow document

4. **Direct Instruction: Competitive Analysis** (15 min) `[EQ1, K3, S1, S2]`
   - **I do:** Explain competitive analysis: Find 2-3 apps solving similar problems
     - What do competitors do better? Worse?
     - Show example comparison matrix (features down the left, apps across the top)
   - **I do:** Demonstrate with 3 weather apps—quick comparison of how each handles the same task
   - Key insight: Competitors have already tested solutions; learn from their successes and failures

5. **Introduce Project B: Make It Better App** (10 min) `[EQ1, EQ2, U1, S1]`
   - Overview: Choose an app that frustrates you, analyze what's broken, redesign the core experience
   - App selection criteria:
     - 💚 An app you actually use (or gave up on)
     - 💚 Clear purpose it's failing to achieve
     - 💚 Focus on one user flow, not the whole app
     - ❌ Not already well-designed apps (Instagram, Spotify)
   - B1 deliverable (due Day 6 end of class): User Flow + Competitive Analysis PDF
   - Full project due: Day 9 (Feb 9)
   - Bring index cards to next class

6. **Work Session: App Selection & B1 Analysis** (remaining ~55 min) `[EQ1, U1, U2, S1, S2]`
   - Choose your app (instructor approval required)
   - Map the current user flow of the feature you'll redesign
   - Begin competitive analysis: identify 2-3 competitor apps
   - **Continue B1** — User Flow & Competitive Analysis (due Day 6 end of class, PDF to Learning Suite)
   - 1:1 meetings: Help students identify genuine problems vs. personal preferences
